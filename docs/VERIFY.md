## L2/L3 — real host mount

A temporary profile `_mpe2e` was composed from the desktop profile (junctioned `node_modules`) with the plugin installed as a dependency and listed in `dsh.profile.bundles`:

- `dsh --profile _mpe2e --dump-config` produced the `id: media-preview` row, exit 0.
- `dsh --profile _mpe2e --no-open --port 0` booted with no FAILED fiber; the served index referenced `dsh-media-preview/client.js` inside a `plugins/??...` combo and injected `globalThis["__DSH_MEDIA_PREVIEW_CONFIG__"] = {"routePath":"/api/media-preview"}`.
- The combo bundle request answered 200 and contained the `window.__ModuleLoader__.load({ id: "dsh-media-preview", ... })` registration.

## Install shape (desktop profile)

Installed from the npm registry as `dsh-media-preview@^0.1.0`:

- `package.json` `dependencies` plus `dsh.profile.bundles`, and the `media-preview` plugin row appended to `cordis.patch.yml`.
- `dsh plugin --profile desktop ...` is refused by the CLI ("managed exclusively by the Electron application"), so the profile was composed with the runtime's own pnpm (`~/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/pnpm`) and the YAML validated with `js-yaml` (9 entries, the `media-preview` row present).
- `pnpm install --frozen-lockfile --offline` passes.

> Pitfall found during verification: pnpm **copies** a `file:` directory dependency instead of linking it, so editing the source and restarting shows stale code. Re-running `pnpm add` (or installing the packed tarball or registry version) is required.

## Known gaps

- `.mkv` / `.avi` / `.wmv` / `.flv` are registered but Chromium cannot decode them; the player shows its unsupported-codec state. Verified by inspection of the error path, not with a real MKV.
- Multi-range `Range` headers are refused with 416 by design; media elements never send them.
